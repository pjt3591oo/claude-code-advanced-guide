# Comparison units

Find what someone compares between two candidates. Keep those fields in consistent positions so the person can see differences without remembering the previous item. A prominent name is not necessarily the useful comparison.

A worker choosing a shift may compare travel, hours and pay; after accepting, the meeting point and start time lead. The object is unchanged, but the decision has moved on. Let information order follow that change.

An introduction earns first-viewport space if it changes how candidates are understood. Once its message is evident from the list, give the space to actual choices. Count usable comparison units, not visible fragments: a photograph without the identity or price needed to judge it may not yet offer a choice. There is no universal target for visible rows. Shrinking photographs can improve a schedule and damage a comparison that depends on condition; a story may deliberately reveal one subject at a time.

Compare two realistic candidates. If people must repeatedly open details or memorize key values, repair the comparison structure before styling the containers. Keep decisive differences in the list and supporting evidence in the detail.

Preserve the comparison under reflow. Independent records can become labeled groups; a grid whose row and column intersections carry meaning may need local scrolling with identifying headers retained. If the narrow layout turns comparison into a memory task, compactness has removed useful structure.
