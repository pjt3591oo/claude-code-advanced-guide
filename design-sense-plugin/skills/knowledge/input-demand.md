# Input demand

Count the work behind an answer, not only fields or steps. Finding a document, remembering a date, translating a category and correcting rejected input can cost more than typing. Ask for a fact when it changes the outcome; explain an unusual requirement before the person prepares it.

Choose the control from how the answer is known. A copied date favors direct entry; choosing by weekday or availability benefits from a calendar; an approximate recollection may need a period or range. Accept uncertainty when the decision permits it. If execution requires an exact value, explain and help resolve the uncertainty rather than accepting fabricated precision.

Order questions by dependency. Reveal disqualifying prerequisites before expensive work when they can be known. Do not require authentication just to discover public information; authenticate when identity or permission is needed. Resolve answers that determine later questions first. If a later change invalidates earlier work, preserve unaffected answers and identify what must be reconsidered. A shorter path that creates backtracking is not less effort.

Derive constraints from legitimate values and the operation, not tidy examples. Support applicable names, addresses and contact capabilities; reuse known answers with a way to inspect or change them. A remembered answer can be outdated, and reuse does not supply consent. Keep labels, units and essential preparation guidance available during entry.

Probe the flow when a person must look up an answer, lacks an optional capability or changes a prerequisite. Where they must guess, repeat preparation or lose valid work, revise the demand before decorating the form.
