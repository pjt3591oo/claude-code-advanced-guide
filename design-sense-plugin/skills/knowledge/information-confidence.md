# Information confidence

A finished-looking surface can still tell an unfinished truth. Missing, unconfirmed and not applicable are different states. Let the presentation preserve that difference rather than filling every slot.

If a shift listing does not specify meals, the detail cannot promise lunch. Show the uncertainty if it affects the decision, ask before commitment if the answer is necessary, or omit an irrelevant optional field. The decision determines which facts must be collected.

A common default is not automatically a fact. Separate user input, policy defaults and calculated estimates. An estimate needs its relevant assumptions nearby; the same numeral styled as a confirmed total makes a different promise.

Generated replies and summaries make assertions too. Acknowledging a proposed date must not turn it into an agreed appointment. Preserve the distinction between the person's request and what another party has confirmed.

Unanswered and explicitly none are different answers. Preserve that distinction when the choice matters, while allowing a policy default for a reversible preference. A collapsed multi-selection should report the actual selection, with any limit understandable before it blocks another choice. Make clear whether a displayed count includes a named item.

Derived copy must follow the same facts as the controls. Reviewed, available and fulfilled can be independent conditions; finishing one does not establish the others. Different roles can need different next actions while agreeing on what happened. Retire waiting or recovery advice when its cause ends. Count the entity named by the label: several requests from one person are not several people.

Indicators make assertions too. A dot beside a destination can imply unread activity; merely having a saved item does not establish that state. Tie an indicator to a defined condition and clearing behavior. A paging marker needs actual pages and an identifiable current position. If no such information exists, leave the slot empty instead of manufacturing activity.

Use sample content to test variation, not to populate unrelated new objects. Create an item with minimal input, then inspect its list, detail and return state. Every new assertion should have a source in the input, actual policy or calculation. Repair the data-to-presentation boundary when it does not.
